# v0.9.0-alpha.3

Library Tool `0.9.0-alpha.3` is a prerelease that rebuilds both applications:
the desktop at `0.9.0-alpha.3` and Library Tool Capture at `0.5.2-alpha.7`
(`versionCode` 38). It completes the Corrections manager's purpose — cleaning
up photo data captured on a phone — by carrying that work back out to the
phone it came from.

## Corrections travel back to the phone

Photo corrections made on the desktop are published to the cloud library and
installed by Library Tool Capture as a new version of the page. The phone
verifies each corrected image against the untouched camera original before
installing it, and neither the original photo nor the phone's own rendition is
ever overwritten. Text recognition re-runs on the phone against the corrected
pixels, so its regions match what is on screen.

A capture whose corrections were interrupted picks them up on a later sync,
and a page waiting on cloud cleanup is no longer marked failed when a desktop
correction for it lands first.

## Editing in Corrections

- **Book metadata** is now a form with named fields chosen from what the
  record can actually hold, instead of a single block of raw JSON. Anything
  the form does not cover stays editable under **Advanced**. Corrected titles,
  authors, and years continue to reach the phone.
- **Re-OCR** can be run on a corrected image on its own, without redoing the
  image edit. Results arrive as proposals you can read before applying, and
  applying one writes its text and region boxes into the book. A page that
  already holds reviewed work keeps it: the recognition is filed as a proposal
  rather than replacing what a person checked.
- **Region labels** gain *manuscript* (hand-drawn or pencilled annotations),
  *stamp*, and *damage*, alongside marginalia and illustration. Hovering a box
  highlights it, and pressing the label's key while hovering assigns it — no
  click first.
- **Personal library records** have their own panel. It resolves the match a
  phone made to a current row of the master list, still finds the row when it
  has since been edited, proposes candidates for captures that were never
  matched, and approves or rejects them from the desktop. Approving fills only
  blank fields and reports anything that disagreed rather than overwriting it,
  matching how the phone merges. A rejection can be undone.

## Before updating

This release adds a table to the cloud library. Apply
`docs/cloud/migrations/024_capture_corrections.sql` in the project's SQL
editor, then run `python3 tools/cloud_setup.py check`. Until it is applied,
both applications degrade quietly: the desktop reports the corrections stage
as skipped and finishes its sync normally, and the phone ignores the missing
table rather than failing its other syncing.

## Known caveats

- Corrected pages reach captures the phone still lists as recent; a capture
  that has already aged into the archive will not receive them.
- Page reordering and page removal are still not expressible as corrections,
  so they do not travel to the phone.
- Region labels, captions, and categories remain on the desktop; only
  corrected images and book metadata reach the phone.
- Applying recognition to a book that has not been catalogued yet is
  refused; promote the capture first.
