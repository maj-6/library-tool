# v0.8.0-alpha.17

Library Tool `0.8.0-alpha.17` is a desktop prerelease for hands-on testing, and
it ships Library Tool Capture `0.5.1-alpha.11` (version code `30`) alongside it.
Both halves are needed for this release's one feature, so they move together.

## Highlights

- **Scan a box QR, see what is in it.** The Inspect tab used to resolve the box
  correctly and then list only the books that handset still held, so a
  reinstalled or second phone showed an empty crate. It now lists every book
  recorded in that box from your account, read from the cloud, which is where
  every capture is kept.
- **Those books now have names.** The desktop publishes the title, author and
  year it holds for a capture back to the phone. That is the only route by which
  a real title can reach a phone — a capture only carries one of its own when
  the phone that took it had an extraction key.
- **Titles you type on the desktop now arrive.** Editing a Catalogs entry did
  not advance its revision, so the correction changed nothing the phone could
  see and the update was rejected as unchanged. It now advances, which also
  unsticks copyright, scan status and remarks.

## Details

### Box listings

A listing covers the tags a box absorbed through a merge, not just its current
one: merging repoints the desktop catalogue but deliberately never rewrites a
capture's frozen record, so asking only about the surviving box would drop every
book filed under the retired label.

The listing is kept on the phone after it is fetched, so a crate browsed once
stays readable offline, and it is discarded when a different account signs in.
Books this phone still holds always win over their cloud counterparts — those can
open their photos and show live upload status. A cloud-only row is labelled as
such, and is distinguished from a book whose local photos were merely cleared.
An empty box is no longer described as empty in the cloud when the phone could
not reach it.

Listings are scoped to your own captures, so books another contributor filed
into the same physical box are not included yet.

### Catalogue metadata

Captures that have been imported but not yet registered as catalogue entries are
now published too. Registering a capture requires a located scan, so without
this a freshly scanned crate would list untitled indefinitely.

The placeholder given to an untitled capture on import is never published as
though it were a title; such a book lists as untitled instead, which is what it
is. Unregistering a capture again, or re-registering one from a second desktop,
no longer discards the title and author already recorded for it.

## Known caveats

- The Downloads page on the website is not updated automatically at present, so
  this release reaches GitHub Releases but has to be registered separately
  before it appears there.
- A box listing covers your own captures only; multi-contributor crates need a
  sharing decision that has not been made yet.
- Books listed from the cloud show a summary, not their page images.
