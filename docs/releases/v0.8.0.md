# v0.8.0

Library Tool `0.8.0` is the stable desktop release following `0.7.0`. It
publishes Library Tool Capture `0.5.1` (Android version code `31`) alongside
it. This release rolls up the complete desktop 0.8.0 and Android 0.5.1
prerelease series, including the Corrections, capture-archive, box-inspection,
security, and release-gate work completed after alpha.17.

## Highlights

- The desktop now has three complementary book workflows. The book-centered
  Workbench handles cataloguing, source PDFs, OCR, verification, and
  publishing; Replica handles region-aware facsimiles and re-typesetting; and
  Corrections opens as an independent window for image and region review.
- Corrections is backed end to end by the framework-neutral Library Engine.
  Perspective edits, image adjustments, classifications, region roles,
  captions, and review state are revisioned; transform jobs are durable and
  replay-safe; and closing or reopening a Corrections window does not abandon
  accepted work.
- Phone captures now converge on one stable desktop book identity and are
  sealed into recoverable `.lib/3` archives. The desktop and phone exchange a
  revisioned confirmation of whether that archive is current or needs to be
  resealed, without exposing a local archive path.
- Desktop-to-phone sync now returns the catalogue title, author, year, rights
  evidence and status, WHL and Internet Archive availability, scan status,
  remarks, and review state. Phone attention reasons and review requests join
  the desktop review workflow over account sync or paired LAN.
- Library Tool Capture can organize scans into provenance-bearing collections,
  print stable collection tags, scan those tags in Inspect, and list all of the
  signed-in account's books in a box, including cloud-only records retained
  across a reinstall or second phone.
- The desktop adds safer everyday editing: per-tab undo and redo, a shared
  Remarks workflow, recoverable Trash, Smart Scan title-page marking, clearer
  publishing readiness, new themes and theme editing, resource diagnostics,
  contributor profiles, and broad keyboard and contrast improvements.
- The release path now validates the complete Python, JavaScript, Corrections,
  Android, packaging, update-channel, deployment-configuration, and signer
  contracts before either selected product can become public.

## Desktop

### Workbench, catalogue, and recovery

- The Workbench brings catalogue metadata, attached source PDFs, OCR,
  processing alternatives, inline verification, page tools, readiness, and
  publishing into one book-centered workspace. Smart Scan prefers an attached
  local PDF and can pause for keyboard-driven title-page marking before
  scanning a compact selection.
- Undo and redo history belongs to each tab and survives tab switches and
  asynchronous work. Volume labels are consistent across the Library Tool,
  processing jobs, and public Archive Browser without rewriting stored titles.
- Publishing saves the metadata currently on screen before checking readiness
  and presents the title, rights decision, and selected PDF before committing.
  Public text remains withheld until an explicit rights decision permits it.
- Remarks and review targets cover catalogue records, sources, entries,
  Replica pages, published volumes, and phone-originated review requests.
  Replies, resolution, reopening, and navigation stay attached to the exact
  item or physical page.
- Page, entry, manual-record, and translation deletion now goes through a
  bounded Trash with verbatim restore. Restoring advances the item's revision
  and restores page figures and review relationships with the page.
- Home emphasizes recent activity, open review work, and published books.
  Contributor avatars and profile popups, responsive toolbar groups, named icon
  controls, focus restoration, zoom-safe menus, and accessible state labels
  improve navigation at narrow widths and non-default interface scales.
- Porcelain and Slate join the built-in themes. The theme editor supports
  fonts, colors, icons, import, and export, and startup and updater windows use
  the selected palette. Info → Resources reports the source, location, size,
  update time, availability, and record count of local databases.

### Replica, knowledge, and interchange

- Replica can propose typed page regions without replacing protected human
  work. Editors can review and apply proposals, choose text layers, retain
  stable region identities, work with facsimile templates and page colors,
  rework illustrations, and produce re-typeset previews or print-ready PDFs.
- Facsimile rendering can sample a paper tint from PDF margins, follows the OCR
  document that produced its geometry, and preserves word boxes across
  text-only re-OCR.
- Knowledge Test and Ask use structure-aware, versioned passages. The public
  reader adds ranked search within a book, while public catalogue text remains
  subject to the book's rights decision.
- Versioned `.lib` import, export, validation, file association, and open flows
  are implemented outside the web framework. Imports plan and commit
  transactionally, and Replica packages open atomically.

### Corrections

- Corrections is the first independently launchable workbench. The desktop
  window registry supports reuse or a new window, authenticated workbench
  opening, per-profile bounds, and validated portable engine context.
- Books and attention panels lead to an artifact tree, properties, a
  perspective editor, image adjustment, image-category assignment,
  canonical region-role assignment, caption editing, review resolution, and
  optional OCR follow-up.
- Correction reads converge from revisioned filesystem projections. Writes
  carry explicit artifact preconditions, and a reopened window observes the
  accepted image result, classifications, roles, captions, and review state
  rather than reconstructing them from browser memory.
- Transform workers belong to the desktop process rather than a window.
  Submission is idempotent, duplicate acceptance reuses the same receipt,
  cancellation and restart have explicit terminal states, corrected output is
  committed atomically, and a failed OCR follow-up does not roll back a
  successful image correction.
- Original image bytes remain immutable. The engine rejects a transform with a
  mismatched command route, a foreign or stale artifact revision, a linked
  source, a self-aliasing output, an authority that changed during the write,
  or an incomplete receipt.

### Capture intake and round trip

- Importing a fresh phone capture creates one stable book identity and seals
  its portable, path-free `.lib/3` association. Cloud and paired-LAN deliveries
  of the same capture are serialized, so retries cannot create duplicate books
  or competing asset writers.
- Older capture directories can be backfilled resumably. Legacy capture
  identities are preserved when valid, conflicts are surfaced instead of
  overwritten, and interrupted work can resume without discarding a verified
  receipt.
- Catalogue, taxonomy, and canonical metadata changes move a sealed archive
  through a recoverable `current` → `stale` transition. The stale intent is
  retained across a rollout, lost response, concurrent edit, or process
  restart until the exact remote revision is reconciled.
- Cloud acknowledgement atomically publishes the verified association and
  capture status. A lost response leaves the local book durable and repairs the
  remote row on retry; remote photos are cleaned up only after the accepted
  association is known.
- The phone persists a revisioned confirmation and shows a marker only for a
  current archive. Delayed stream identities, out-of-order revisions,
  malformed documents, stale associations, and legacy responses without a
  confirmation remain safely unconfirmed.
- Desktop metadata projections include imported-but-unregistered captures.
  A capture's own recorded title wins when present; otherwise the desktop
  title, author, and year are returned, while the generated placeholder for an
  untitled import is never published as real metadata.

## Library Tool Capture 0.5.1

- Collections are required before capture and freeze their name and origin into
  each book when it starts. Stable, editable tag IDs synchronize across
  devices, remain reserved through rename, deletion, or merge, and support
  printed labels and on-device QR inspection.
- Inspect offers Tiles, Content, and Icons layouts. It combines local books
  with the account's cloud listing, follows authoritative merged-tag aliases,
  labels cloud-only and locally cleared books distinctly, and retains a fetched
  listing for offline browsing until the signed-in account changes.
- A photo-free collection inventory preserves the bibliographic summary needed
  for box browsing after delivered media is cleared. Long scan histories keep
  one collection expanded and page rows in bounded windows.
- Camera controls include tap-to-focus, autofocus lock, zoom, exposure,
  continuous light, Fast and More Detail profiles, sharpening, a page-margin
  guide, and a fixed portrait or landscape orientation. The current book also
  shows a persistent elapsed timer.
- Realtime voice notes recognize Price, Pages, Condition, Illustrations, and
  Remark. Start/end notes, restart, undo, and edit commands are hardened around
  in-flight photos, backgrounding, and partially recognized speech.
- **Sync captures** is explicit. Pressing it freezes the eligible captures and
  chosen destination; lifecycle work, capture completion, and background OCR
  cannot silently begin or expand a batch.
- Scan rows and book details show compact catalogue, availability, scan,
  remarks, attention, review, and archive-confirmation state. Details add photo
  roles, OCR-region overlays, corrected-display and retained-original views, a
  carousel, and collapsible extraction diagnostics.
- Corrected cloud artifacts are validated before atomic installation. Camera
  originals stay safe, pending cleanup uses softened thumbnails, and OCR-region
  geometry is regenerated for perspective and page-curvature transforms.
- About contains the packaged changelog and documentation. Update checks can
  refresh a validated catalogue of Android strings and icons but continue to
  hand APK installation to the browser because the app is not Play Store
  certified.

## Security and integrity notes

- Provider credentials no longer travel through ordinary settings or browser
  state. The engine owns a protected secret repository, account-scoped
  synchronization, migration of earlier saved values, replacement and clearing
  recovery, and capability-based provider discovery.
- The packaged desktop sidecar requires its authenticated local client and
  rejects unexpected origins, routes, workbench contexts, or transport
  envelopes. Corrections filesystem authorities are checked before and during
  writes, including Windows file-identity changes and POSIX ancestor changes.
- `.lib/3` capture identities must be portable single-segment names and may not
  collide with reserved Windows device names. Readers bound JSON nesting and
  strings, require unique integer page lists to match physical page members,
  and make the framework-neutral reader and engine planner enforce the same
  rules.
- Capture metadata, multipart requests, photo counts, and individual photos
  are bounded. Cloud downloads enforce the photo-size ceiling against both the
  advertised length and streamed body, and one malformed row is isolated
  instead of corrupting the rest of a sync.
- Cloud migrations 020–022 protect archive confirmation with a revisioned
  association and an exact-scope, short-lived two-party capability. The
  signed-in capture owner or assigned contributor binds the capture,
  association, expected revision, and requested status; the owner's protected
  backend credential can consume only that bound capability. Direct association
  writes are denied, exact consumed requests remain replayable for lost-response
  recovery, and ownership, grant, revision, document, or status changes fail
  closed.
- Production Pages configuration is generated only from validated public
  settings. Placeholder, preview, malformed, or privileged-key configuration
  cannot be promoted as a production deployment, and a failed rerun removes
  any previously generated deployable configuration.
- Android packaging is release-key-required and verifies the APK certificate
  against the repository-pinned SHA-256 fingerprint. Desktop update metadata
  must name the expected installer and version, and publication accepts only
  the allowlisted installer, update manifest, blockmap, and APK.

## Validation notes

The `v0.8.0` tag workflow blocks packaging until both repository and Android
validation succeed:

- Ruff, the complete Python suite, JavaScript syntax checks, and the complete
  JavaScript behavior suite run from committed dependencies.
- The Corrections release gate drives the real engine client over the
  production loopback transport and filesystem composition. It exercises
  classification, region roles, captions, perspective geometry, image
  adjustment, OCR follow-up failure, Space submission, window replacement,
  persisted results, capture sealing, cancellation, interruption, exact replay,
  immutable originals, accessibility contracts, and bounded artifact browsing.
- Android runs unit tests, debug and release lint, and a debug assembly before
  the signed release APK is built. Association confirmation tests cover
  current, stale, malformed, delayed, and restarted states, and the packaging
  job verifies the release signer.
- The frozen desktop sidecar is smoke-tested in isolation before the Windows
  installer is assembled. Release-policy tests verify exact version agreement,
  stable/prerelease channel classification, Android version-code monotonicity,
  allowed assets, update metadata, draft-first publication, and safe reruns.

Automated validation does not replace a physical-device camera and QR smoke
test, a live external OCR-provider test, a real Chromium/screen-reader pass, or
a signed Windows installer exercise on a clean machine. Those remain the final
manual release checks.

## Deployment notes

- An existing cloud project must contain every ordered migration through
  `022_capture_lib_association_capability.sql`. Migrations 018 and 019 establish
  collection tags and their permanent reservation rules; migrations 020
  through 022 establish the revisioned capture-archive acknowledgement and its
  publication protocol.
- Run `python tools/cloud_setup.py check` before tagging. It reports pending
  migrations, verifies the expected tables, views, columns, and buckets, and
  smoke-tests anonymous access boundaries. Apply pending files in order.
  Migrations are append-only and idempotent; never edit or remove an applied
  migration.
- Deploy schema changes before enabling 0.8.0/0.5.1 capture confirmation.
  Without the required protected owner credential or schema capability, a
  locally sealed capture remains remotely pending for a later retry instead of
  being marked imported without its verified association.
- Rebuild and redeploy the optional image processor from the stable tag so its
  pinned `world-herb-library==0.8.0` dependency and shared raster kernel match
  the desktop release.
- A plain `v0.8.0` tag selects the stable channel. Because the desktop version
  and Android version identity both advanced, the release must publish both
  products or remain unpublished. The workflow keeps the GitHub release as a
  draft until every selected, allowlisted artifact has uploaded successfully
  and then registers the download rows.
- A tagged Android build requires the public project values, the existing
  release keystore, and its matching pinned certificate. A missing or different
  key is a hard failure. Windows signing remains dependent on the configured
  release certificate; an unsigned or privately trusted installer may still
  trigger SmartScreen.
- The Downloads page reads release rows directly, so publishing a release does
  not require a static-site redeploy. If the website itself is redeployed, use
  the validated production configuration; fixture-preview output is for
  artifact inspection only.

## Upgrade notes

- Back up the desktop library before upgrading, especially if it contains phone
  captures or active correction work. Normal `0.7.x` installs can update in
  place and keep their existing data.
- Historical desktop `3.x` builds do not auto-update to `0.8.0` because the
  version number was reset to the pre-1.0 `0.x` line. Those installs need a
  one-time manual reinstall. The installer preserves library data by default.
- Earlier provider keys are migrated automatically into the protected engine
  store. Existing capture directories are backfilled and associated
  resumably; let the process finish or resume it later rather than deleting its
  receipts or archive state by hand.
- Existing `.lib/1` and `.lib/2` packages retain compatibility. `.lib/3` is the
  sealed capture-archive graph used for new phone imports and should be moved
  together with its catalogue data rather than rewritten manually.
- Library Tool Capture `0.5.1` has version code `31`, so it installs over
  `0.5.1-alpha.11` (code `30`) when signed with the same release key. An app
  update retains settings, collections, inventories, capture queues, and open
  capture state; uninstalling the app does not provide that guarantee.
- Android collection stores upgrade deterministically. An open capture created
  by an older build estimates its timer start from the oldest durable capture
  sidecar when no explicit start timestamp exists.
- Cloud operators should apply the stable schema before users run the first
  post-upgrade sync. Client retries are designed to preserve local books and
  pending confirmations, but schema readiness avoids an unnecessary pending
  cycle.

## Known limitations

- Corrections is the first independent workbench, not yet a complete
  multi-workbench project manager; all modules still ship together.
- Importing the non-empty capture graph from a `.lib/3` archive into an
  already-existing catalogue item is refused until the raster/spatial
  persistence adapter is available. Sealing and promoting a fresh capture is
  supported.
- Corrections can commit an image transform when OCR follow-up is unavailable,
  but no production follow-up provider is bound yet; the image succeeds and
  the OCR request reports its separate failure.
- A box cloud listing contains the signed-in account's captures and
  bibliographic summaries, not another contributor's books or remote page
  images.
