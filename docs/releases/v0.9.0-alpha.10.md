# v0.9.0-alpha.10

Library Tool `0.9.0-alpha.10` is a desktop-only prerelease fixing one bug in
`0.9.0-alpha.9`. Library Tool Capture remains at `0.5.2-alpha.12`; Android's
version identity is unchanged, so this build does not replace its APK.

## The Corrections editor loads its books again

On `0.9.0-alpha.9` the Books panel could sit on "Loading books and capture
summaries…" forever — never populating, and never showing an error either.

It was a livelock rather than a slow read. The editor's convergence poll
cancelled whatever index request was already in flight and started a new one,
and while the first load is still running it did that on every single tick. Any
library whose index read is slower than the poll interval could therefore never
finish, and because the cancellation was discarded rather than reported, the
panel had no error to show.

This library's index reads in 2.1s against a 2s poll, so it lost that race
every time.

The race is older than the symptom. Until `0.9.0-alpha.9` the poll learned the
index revision by rebuilding the whole index, which made it exactly as slow as
the read it was interrupting — it could never get far enough ahead to starve
it. Making that check cheap is what turned a harmless race into a permanent
one.

A convergence notice now joins the request already in flight instead of
restarting it. It only reports that the revision may have moved, which is what
the running read is already fetching. Explicit refreshes are unchanged: a
manual refresh, a workspace change, and a mutation all still supersede the
request in flight.
