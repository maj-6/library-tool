# v0.9.0-alpha.12

Library Tool `0.9.0-alpha.12` is a desktop-only prerelease. Library Tool
Capture remains at `0.5.2-alpha.12`; Android's version identity is unchanged,
so this build does not replace its APK.

## The Corrections editor is fast on a large library

Measured against a copy of the affected 1000-book, 3000-capture library:

- The books list paints in about a second instead of five to eight — the
  editor now loads a small summary first and fills in per-book detail in
  parallel windows, instead of waiting on one monolithic index.
- Clicking a book or capture while anything refreshes stalls at most ~0.6s
  instead of 3–5s, because no request holds the workspace busy for longer
  than one detail window.
- Resolving a review and stepping to the next book converges in 0.29s
  instead of rebuilding the whole index for five seconds.
- Repeat index builds stop re-reading unchanged captures: navigation data is
  cached against the capture manifest's content and each image file's
  identity, and re-verified on every use. A changed file always rebuilds.

## Region boxes and the perspective quad draw at the correct scale

The editing surface could end up shorter than the photo inside it, which
drew every region box at ~64% scale and — worse — recorded wrong
coordinates for corner drags in the lower part of the photo. The surface now
always matches the photo exactly. Transforms committed from earlier builds
whose quads never reach the lower frame may carry compressed coordinates.

## Image processing is fully adjustable

The six processing operations that shipped in `0.9.0-alpha.9` — unsharp
mask, kernel sharpen, gamma, contrast, per-channel gains, and white balance —
now have real controls in the Image Adjust panel: add, reorder, remove, and
tune each operation, and save the pipeline as a named preset. The "Contrast"
readout that sat pinned at 100 was actually the grayscale/threshold blend
weight; it is now a real input labeled Binarize, and true contrast lives in
the operations list.

## CH candidates preview in Item Properties

When a capture-backed book has candidates from the CH master list, empty
fields show the top candidate's value with a soft amber highlight. Previews
are display-only — they are never saved with the item — and approving or
rejecting the match stays in the CH panel.
