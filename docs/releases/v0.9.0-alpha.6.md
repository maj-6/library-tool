# v0.9.0-alpha.6

Library Tool `0.9.0-alpha.6`, released alongside Library Tool Capture
`0.5.2-alpha.11`. Both halves change together here: the phone now records what
part of a book each photo shows, and the desktop's extraction reads that label.

## Extraction is told which page it is reading

Photo text used to reach the cataloguing model as one undifferentiated block, so
it could not tell a title page from a spine from a bookseller's pencilled note.
Each block is now tagged with its role and the prompt ranks them — title page
first, cover second, spine only for the spine title, and endpapers, dealer
descriptions and price tags treated as untrusted for every field.

- **Bookseller and library marks are no longer read as publication dates.** A
  dealer's "6/52" had been taken as the year 1952 for an Edwardian book.
- **A capture with no readable text no longer gets invented metadata.**
  Unreadable pages come back as image placeholders rather than as an empty
  result, which counted as text and let the model answer from memory. One
  capture was catalogued as Gibbon's *Decline and Fall* on the strength of two
  photos that OCR could not read at all. Extraction now reports that it could
  not read the capture.

The extraction prompt exists in two copies, one per runner, and they had quietly
drifted apart despite the Kotlin copy claiming to be verbatim from the Python
one. They are identical again, and a test now holds them there.

## A staged review of every cloud capture

`data/capture-review/staged_review.json` records a review of all 555 captures
currently in the cloud, judged against each capture's own OCR text and then
re-checked by an adversarial pass that rejected 7 of 134 proposals. It proposes
106 field changes across 96 captures, flags 122 for a human eye, marks 57 as not
books, and assigns roles to all 2,005 photos.

**Nothing in it has been applied.** Apply it with:

```
python tools/apply_capture_review.py --review data/capture-review/staged_review.json
```

That is a dry run; `--apply` writes, after backing up `manual_entries.json` and
skipping any field whose live value has drifted from the reviewed one.

Note that only `title`, `author` and `year` reach the handset — the capture
metadata projection publishes a deliberately bounded three-field snapshot — so
staged `subtitle` and `publisher` corrections stop at the desktop catalogue.

## Updating

Windows installs update in place from the previous prerelease. This build is
flagged as a prerelease, so a stable install is not offered it unless
**Settings → Updates → include prerelease updates** is on.
